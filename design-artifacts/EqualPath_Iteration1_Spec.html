改动 1 · Recurrence

周重复模式 + 物化成真实记录

之前：每条 work_commitments / care_commitments 都是 date + start_time + end_time。没有重复规则、没有模板、没有导入。她每周手输约 15 条。

改动 2 · Handover

覆盖结束于孩子被接走的那一刻

之前：「工作 18:00 结束、TASKA 18:00 关门 → 已覆盖」。pickup、drop-off、commute 在整份 epics 文档里出现 0 次。

之后：覆盖记录带 collect_by（提供者允许的最晚接走时间）与 handover_out_ref（谁去接）；用户档案带三个手填的通勤分钟数。系统算出接送人的实际到达时间，把差额作为一段交接缺口喂给现有的区间规则。

顺带修掉的一个矛盾：架构评审 R1.2 要求每天扫描未来 14 天，但原 AC 1.1.3 拒绝任何落在"展示的规划周"之外的日期 —— 14 天外根本没有数据。改动 1 落地后，规划视野统一改为滚动 14 天，AC 1.1.3 的措辞随之更新。这条在 rev B 里已经改掉。

这一版没有动的一件事：架构评审的问题 A（plans.conflict_ref 指向不存在的 conflicts 集合）。物化冲突是一个独立决定，你还没拍板，所以到 rev C 为止都没有替你加。它仍然是 ERD 上的一个悬空引用。

03 / 算法规格

四个纯函数，按这个顺序跑

Deterministic, testable, no external calls

A1 · 模式物化 materialise-schedule

输入：user_id, horizon_days = 14 · 输出：写入/更新的占位记录

# 幂等：键为 (pattern_id, date)。覆写过的记录永不被触碰。
for pattern in active_patterns(user_id):
    for date in range(today, today + horizon_days):
        if weekday(date) not in pattern.byweekday:        # 不在这周几
            continue
        if date < pattern.effective_from:                 continue
        if pattern.effective_until and date > pattern.effective_until: continue

        existing = find(pattern_id=pattern.id, date=date)
        if existing and existing.is_override:               # 用户改过，尊重她
            continue
        upsert(target_table(pattern.kind),
               pattern_id=pattern.id, date=date,
               start_time=pattern.start_time, end_time=pattern.end_time,
               is_override=False, **pattern.payload)

# 模式被删除或缩短 effective_until 时：删除视野内所有 is_override=False 的后代记录

触发时机：① 模式创建或修改后立即跑一次（只跑该模式）② 每日 cron 跑一次全量，把视野往前滚一天。这就是 R1.2 那个 14 天扫描能成立的前提 —— 先有记录，才扫得到冲突。

A2 · 覆盖合并与缺口 compute-gaps

输入：某个 child 某天的所需窗口与全部覆盖记录 · 输出：未覆盖区间列表

merged = merge_overlapping(sort_by_start(coverages))   # 重叠先合并，避免重复计数
gaps   = subtract_intervals(required_window, merged)
return [g for g in gaps if duration(g) > 0]        # 零长度不是缺口

A3 · 交接缺口 compute-handover-gaps 新

输入：某天的覆盖记录 + 用户通勤分钟数 + 接送人的工作安排 · 输出：额外的未覆盖区间

# ── 傍晚：她赶不及在 TASKA 关门前到 ──────────────────────
for cov in coverages_with(collect_by):
    collector = cov.handover_out_ref
    blocking  = last_commitment_ending_before_or_at(collector, cov.collect_by)
    eta       = blocking.end_time + travel(blocking.location → cov.location)
    if eta > cov.collect_by:
        emit_gap([cov.collect_by, eta], reason="handover_out")

# ── 早晨：TASKA 开门太晚，她赶不上上班 ───────────────────
for cov in coverages_with(open_from):
    dropper   = cov.handover_in_ref
    first     = first_commitment_starting_after(dropper, cov.start_time)
    must_leave_by = first.start_time − travel(cov.location → first.location)
    if cov.start_time > must_leave_by:
        emit_gap([must_leave_by, cov.start_time], reason="handover_in")

为什么这样设计：交接缺口输出的就是一段普通的"未覆盖照护区间"，直接喂给 A4。AC 2.1.1 的区间规则一个字都不用改，18 条既有 AC 全部原样存活。这是最小侵入的做法。

具体长什么样：TASKA 18:00 关门（collect_by = 18:00），她的客户会 18:00 在办公室结束，办公室→TASKA 手填 35 分钟 → ETA 18:35 → 生成一段 [18:00, 18:35] 的缺口，35 分钟，孩子无人照看。这段在原设计里是完全不可见的。

A4 · 冲突检测与排序 detect-conflicts

输入：A2 + A3 的全部未覆盖区间 + 当天工作安排 · 输出：冲突列表

for gap in (gaps_from_A2 + gaps_from_A3):
    for w in work_commitments(date):
        if gap.start < w.end and w.start < gap.end:      # 唯一的区间规则
            overlap = [max(gap.start,w.start), min(gap.end,w.end)]
            if duration(overlap) > 0:                     # 相接不算冲突
                upsert_conflict(key=(child, date, gap), 
                                minutes=duration(overlap), at_risk=w, source=gap.reason)

# 排序：确定性，可复现
sort_key = (0 if (w.fixed and not w.remote_possible) else 1,  w.start_time,  w.id)
